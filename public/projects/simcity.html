Sim City 4 - Sync Region addon

My first official Mod for a game with over 100+ downloads!

Role: Product owner and developer Timeframe: 1 month Tools: C++, Visual Studio, Github
Download the mod View the code on GitHub

Overview

You have probably heard of the SimCity series, but not everyone knows that even 20 years after its release, SimCity 4 is still popular. Possibly the best in its genre, I keep returning to it over the years, and I have always wanted better quality-of-life tools for it.

So I built one!

The Problem

This addon solves a problem I had for quite a while:
ensuring that all cities are updated is both time-consuming and repetitive.

In order to ensure all are in sync, a person had to load into a city, let it run for a while, save, and then repeat for every other tile.
My issue was that unlike the SimCity 2013, regions are not automatically in sync, and letting a few neighbours fall behind often causes problems to the city as they equalise. There is no simple way to solve this problem in-game, however this DLL is effectively a macro that let each city run and save from a single command.

Approach and build

Starting point

I have used mods before, however there was a recent breakthough that allowed accessing much more, by using DLL's. Originally I thought of using AutoHotkey to mimic the user's input, but reading on the DLL's realised that there was a much better, elegant way to handle it: commanding the existing game logic.

End goal was to use the game engine's internal commands to scan the region, then step through each city tile in turn: load it, run the simulation for a configurable number of months, save, and exit, repeating across the whole region. This resynchronises cross-border data that would otherwise only update through manual play.

Working with an outdated engine

The main challenge was working without documentation.
It was my first time using C++ and even while using other addons as an example to build upon, I had to reverse-engineer the game's internal commands, piece together what references I could find, exchange notes with others on the modding forums, and work through several failed approaches before landing on one that was stable.

In the end, I have discovered about 6 methods that did not work and had to build several testing methods to validate edge cases, before finding a valid solution.
For example, even simple things like loading a .ini file had problems, as it had to be a forced "headerless" file to read it correctly, otherwise it errored out.
This doesnt even touch on the scale where people use different versions, different addons and operating systems, all that needed to be tested for compatibility.

Since I was building something that was uncharted territory, I deliberately wrote down all test and findings into a Github documentation, so others can learn from my research and be inspired to build even better things with it!

Outcome and impact

1000+ page views as of Sept 2026
103 downloads
10+ minutes saved on average region
1 delivered product!

Originally I thought I may be the only one who had this issue. That was not the case, and it is very nice to see that my personal project has helped others. The results were overwhelmingly positive, both as reception and download numbers.
Both on Simpropolis and Reddit, it was welcomed as a nice quality-of-life addon. I also know that this project has inspired other developer to create another mod based on my findings!

To quote one:
"I have always wondered whether something like this exists, delighted to hear it now does!"

Reflection

I loved working on this, as the many years of playing this game has given me a very good background knowledge of how things work, what are pitfalls to avoid, and what are possible avenues to make this happen. This just validated for me the importance of research and discovery, as otherwise I would have spent much, much longer time to get the same results.

Perhaps most importantly of them all, this one had a direct impact with me and the community. Many projects are handed-off and never to be seen again. This one I could see on what people reacted, why they were happy to use it.
It has provided with me with a passion to continue and see how it helps others, called "ikigai".
This made me ensure that all my findings are documented and accessible, so others can take what I built and continue with new ideas, just as I did with theirs.
